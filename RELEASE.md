# Release Guide

PIV Signer is ready to be distributed in two ways:

| Path                                | Effort   | Recommended for                          |
| ----------------------------------- | -------- | ---------------------------------------- |
| **Developer ID + Notarization**     | Low      | Internal / direct download / open-source |
| **Mac App Store**                   | Higher   | Public discovery, automatic updates      |

The repo is configured so both paths work without code changes. The
choice is just which signing identity you use and where you upload.

---

## What is already prepared in the repo

- `PivSigner.entitlements` — App Sandbox enabled, with the four
  capabilities the app actually needs:
  - `com.apple.security.app-sandbox`
  - `com.apple.security.smartcard` — read identities from PIV tokens
    via `kSecAttrAccessGroupToken` and `TKTokenWatcher`
  - `com.apple.security.files.user-selected.read-write` — write the
    `.p7m`/`.p7s` next to user-picked files
  - `com.apple.security.files.bookmarks.app-scope` — security-scoped
    bookmarks for the custom output folder
- `PrivacyInfo.xcprivacy` — privacy manifest declaring use of
  `UserDefaults` (CA92.1) and file-timestamp APIs (C617.1, 0A2A.1).
  Required by Apple since May 2024.
- `Info.plist` (generated by `Scripts/build-app.sh`) includes
  `LSApplicationCategoryType=public.app-category.utilities`,
  `ITSAppUsesNonExemptEncryption=false` (digital-signature use is
  exempt from US export compliance), `LSMinimumSystemVersion=13.0`,
  and proper localization metadata.
- `Scripts/build-app.sh` assembles a hardened-runtime, sandbox-correct
  bundle and codesigns it if `SIGN_IDENTITY` is provided.
- `Scripts/notarize.sh` automates `notarytool` submission and
  stapling.
- All file access via `NSOpenPanel` / drag-and-drop / security-scoped
  bookmarks — there is no hardcoded path access that would fail in
  sandbox.

## Path A — Developer ID + Notarization (outside Mac App Store)

Best for: distributing via your website, GitHub Releases, or company
intranet. Users download the app, double-click to install. Gatekeeper
opens it without warnings because it is notarized.

### One-time setup

1. **Apple Developer Program** membership ($99/year) at
   https://developer.apple.com/programs/.
2. In **Xcode → Settings → Accounts**, sign in with your Apple ID
   linked to the membership.
3. Create a **Developer ID Application** certificate:
   Xcode → Settings → Accounts → Manage Certificates → "+" → Developer
   ID Application. The certificate appears in Keychain Access.
4. Create an **app-specific password** at
   https://appleid.apple.com → Sign-In and Security → App-Specific
   Passwords. Save it.
5. (Recommended) Store credentials in Keychain so scripts don't need
   plain-text passwords:
   ```bash
   xcrun notarytool store-credentials AC_PASSWORD \
       --apple-id you@example.com \
       --team-id YOURTEAMID
   ```

### Each release

```bash
SIGN_IDENTITY="Developer ID Application: FieldHub Inc. (TEAMID)" \
    ./Scripts/build-app.sh

NOTARY_PROFILE=AC_PASSWORD ./Scripts/notarize.sh
```

The signed, notarized, stapled `.app` ends up at
`dist/PIV Signer.app`. Wrap it in a `.dmg` if desired, then upload to
your distribution channel.

### Optional: auto-updates

Add Sparkle (https://sparkle-project.org), publish an `appcast.xml`
alongside the DMG. Users get automatic update prompts.

## Path B — Mac App Store

Best for: maximum discoverability, automatic updates, parental
controls, family sharing.

### One-time setup

1. **Apple Developer Program** membership.
2. **App Store Connect** record:
   - https://appstoreconnect.apple.com → My Apps → "+" → New App
   - Platform: macOS
   - Bundle ID: `com.fieldhub.PivSigner` (must match `Info.plist`)
   - SKU: `piv-signer`
   - Primary language: English
3. Fill in store metadata:
   - **Name** — *PIV Signer*
   - **Subtitle** — e.g. *Sign files with your YubiKey*
   - **Description** — see suggested text below
   - **Keywords** — `PIV, YubiKey, smart card, sign, CMS, PKCS7, p7m`
   - **Support URL** — your support page or GitHub Issues
   - **Marketing URL** — optional
   - **Privacy Policy URL** — required even though we collect nothing.
     A simple page stating "PIV Signer does not collect, store, or
     transmit any user data" suffices.
   - **Category** — Utilities (already in Info.plist)
   - **Content rating** — none, no objectionable content
   - **Pricing** — free or paid
4. Create a screenshot set at one or more required sizes:
   - 2880 × 1800 (16:10) — primary
   - 1440 × 900 — secondary
   The app is unilingual per locale on store; if you want all three
   languages on the listing, provide screenshots for each.

### Build for App Store

The cleanest path is via Xcode (15+) opening `Package.swift`
directly. CLI archive against a SwiftPM package is awkward and not
worth setting up for a single distribution.

1. `open Package.swift` (in the project root) — Xcode opens the SwiftPM
   package as a workspace.
2. Select the `PivSigner` scheme. *Product → Destination → My Mac.*
3. Click the **PivSigner** target → **Signing & Capabilities**:
   - Team: your Apple Developer team
   - Signing certificate: *Apple Distribution*
   - Bundle ID: `com.fieldhub.PivSigner`
   - Add capability: **App Sandbox**
     - Tick: *Smart Card*
     - Tick: *User Selected File* → Read/Write
     - Tick: *Bookmarks* → App Scope
4. Build → Archive (`Product → Archive`).
5. In **Organizer**, click *Distribute App* → *App Store Connect* →
   *Upload*. Xcode handles signing and uploading.
6. Back in App Store Connect, the build appears in 5–30 minutes.
   Attach it to the version, fill remaining metadata, **Submit for
   Review**.

### App Store review notes

PIV Signer is a security-related utility that uses smart cards. Apple
review tends to ask:

- "Why does the app need the Smart Card entitlement?" — to read the
  user's PIV certificate and produce signatures with the on-card
  private key. The system PIN dialog is the standard
  CryptoTokenKit-mediated UI; the app never sees the PIN.
- "What does the app do with user files?" — reads the user-selected
  file via `NSOpenPanel` / drag-and-drop, signs it via Apple's
  `CMSEncoder`, writes the resulting CMS container next to the source
  (or to the user-selected output folder).
- Provide a working **Demo / test account** is N/A — there is no
  account, no network, no server.
- Mention that **no data leaves the device** — important for trust.

Review usually takes 1–3 business days for a small utility like this.

## Pre-submission checklist

Before submitting, run through this in either path:

- [ ] `swift build -c release` succeeds with no warnings
- [ ] `./Scripts/build-app.sh` succeeds and produces a working `.app`
- [ ] App opens, shows the app icon in Dock/Finder, About window has
      the right version and links
- [ ] Sign mode works end-to-end with a real PIV card and produces a
      valid `.p7m`
- [ ] Verify mode opens the same `.p7m` and shows green "valid"
- [ ] Settings → Profiles: add / duplicate / delete / select all work,
      changes survive app relaunch
- [ ] Drag-and-drop of multiple files works
- [ ] Custom output folder via security-scoped bookmark survives a
      relaunch
- [ ] Localizations: switch system language to RU and UK in System
      Settings → Language & Region, confirm UI translates
- [ ] `codesign --verify --deep --strict --verbose=2 "dist/PIV Signer.app"`
      reports `valid on disk` and `satisfies its Designated Requirement`
- [ ] (Path A) `spctl -a -t exec -vv "dist/PIV Signer.app"` reports
      `accepted` after stapling
- [ ] (Path B) Archive validates in Xcode Organizer with no errors

## Suggested store description

```
PIV Signer turns any PIV-capable smart card — including YubiKey 5,
SmartCard-HSM, and any token macOS recognizes through CryptoTokenKit
— into a one-click file-signing tool.

Drop one or more files, pick a profile, enter your card PIN, and PIV
Signer produces a CMS / PKCS#7 container with your digital signature.
Verify any signed file, inspect signer certificates, and extract
embedded payloads — all without installing OpenSC, libp11, or any
external runtime. Everything is built on macOS's own Security and
CryptoTokenKit frameworks, so signatures are produced by the OS, not
by us.

Features:
• Sign into embedded (.p7m) or detached (.p7s) CMS containers
• SHA-256 / SHA-384 / SHA-512 digests
• Sign / verify with one click; batch sign multiple files at once
• Configurable certificate-chain inclusion
• User-managed signing profiles
• Native certificate inspector (the same dialog as Keychain Access)
• 100% on-device; nothing is ever transmitted
• Localized in English, Russian, and Ukrainian

PIV Signer is open source under the Apache 2.0 license.
```

## Roadmap items affecting future submissions

- **RFC 3161 trusted timestamps** — once implemented, will require
  outbound HTTP to a TSA URL. Add the entitlement
  `com.apple.security.network.client` to `PivSigner.entitlements`.
  Some TSA URLs may require a specific privacy reason — declare in
  privacy manifest if Apple flags it during review.
- **Auto-updates (Sparkle)** — only relevant for Path A. App Store
  handles updates itself.
